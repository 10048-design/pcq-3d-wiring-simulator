# PCQ 3D 배선 실습 시뮬레이터

## 최신 작업: 핵심 3D (2026-09-12)

`npm run dev` 실행 후 [핵심 3D 실습](http://127.0.0.1:5173/3d.html)을 엽니다. 목록의 **핵심 3D 실습 열기**로도 진입합니다.

시작 → 재료 선택 → 피복 제거 → 압착 장착 → 시작 단자 → 필요 시 CT 경유 → 도착 단자 순서입니다. 기구 선택/확대, 곡선 배선, 끝점 자재 수정, 완료 잠금, NET/JUMP 채점과 JSON 내보내기를 지원합니다. Three.js 실행 파일은 로컬에 포함되어 있습니다. 새 개발 환경의 테스트 의존성 설치는 `npm ci`입니다.

**최신 인수인계 및 정확성 범위는 [docs/PCQ_IMPLEMENTATION_STATUS.md](docs/PCQ_IMPLEMENTATION_STATUS.md)를 우선 확인하세요.** 주요 제품 공식 치수와 단자 번호를 반영했지만 실측 좌표, 미식별 제품과 브라우저 실사용 검증은 확인 필요입니다. 아래 설명은 보존된 기존 2D 프로토타입에 대한 내용입니다.

PDF 26개를 날짜별로 선택해 3D 배선과 채점을 연습할 수 있습니다. 각 PDF는 첫 6페이지만 사용합니다.

## 실행

Node.js가 있는 PC에서 이 폴더를 열고 `npm run dev`를 실행한 뒤 http://127.0.0.1:5173 을 엽니다. 추가 패키지 설치와 AI API 키가 필요하지 않습니다.

`npm test`로 채점과 시험 상태 전환을 검사하고, `npm run build`로 156개 문제 페이지, 26개 문제별 기구/정답 프로필과 실행 파일을 검증합니다. 배포 전에는 `npm run deploy:check`를 실행합니다. 이 프로젝트는 별도 번들링이 필요 없는 정적 웹앱입니다.

## 연습

문제 확인하기 → 자료 확인 및 PLC 전원 AC/DC 선택 → 시작 → 작업판 기구 선택 → 시작 단자 선택 → 전선·양쪽 압착단자·절연튜브 설정 → 도착 단자 선택 → 완료 확인 → 채점하기 → 오류 클릭 → 다시 풀기.

전선의 수정 버튼은 자재와 양쪽 접속부 상태를 변경합니다. 연결 목적지를 바꾸려면 해당 전선을 삭제하고 다시 연결합니다. 실행취소가 지원됩니다. 완료 후에는 모든 배선 변경이 잠깁니다.

완료된 최종 시간과 배선은 현재 브라우저의 로컬 저장소에 보관합니다. 서버나 다른 사용자에게 보내지 않습니다. 진행 중 새로고침 시에는 작업 손실 경고를 표시합니다. 자동 복원 및 작업 이력 화면은 현재 범위에 없습니다.

## 정확성 범위

현재는 **검증용 부분 채점 프로토타입**입니다. 실제 제품을 정하지 않고 물리 단자 위치를 추측하지 않았습니다. TB 단자는 원본 배치 위에서 직접 선택하고, 나머지는 기구를 선택한 뒤 단자 목록으로 연결합니다. 원본에 실물 번호가 없는 PB·SS·램프는 도면상 접속부 기능명을 사용합니다.

Y형 압착단자 방향과 2개 체결 방향은 원본 1~6페이지에 구체적인 기준이 없어 저장만 하며 정오를 판정하지 않습니다. SMPS/전원 보호도체는 1페이지 TB4 지시와 5페이지 TB2 E 그림이 상충하여 전기적 판정을 보류합니다. 기구 접촉·음영 경로·타이 상태는 사용자가 입력한 상태에 대한 검사이며, 그려진 선을 기하학적으로 검사하지 않습니다. 실제 실습용 인증 또는 공식 채점 도구로 확정한 상태가 아닙니다.

전체 분석과 검증 항목은 `docs/검증보고서.md`에 정리했습니다. 문제별 원문과 규칙 재정의는 `dist/catalog.json`, 공통 규칙은 `dist/common-rules.json`, 공통 NET은 `dist/problem.mjs`, 문제별 회로 변형은 `dist/problem-profiles.mjs`, 독립 채점 로직은 `dist/engine.mjs`에 있습니다.

## URL 공유 배포

`dist` 폴더를 정적 웹 호스팅에 그대로 올릴 수 있습니다. HTML, MJS, JSON, WebP를 같은 출처에서 제공하면 서버 계산, 계정이나 생성형 AI API 없이 동작합니다.

- Netlify: 저장소를 연결하면 루트의 `netlify.toml`이 검증 명령과 `dist` 게시 폴더를 적용합니다. 또는 `dist` 폴더를 수동 배포할 수 있습니다.
- Vercel: 저장소를 연결하면 `vercel.json`의 `npm run build`와 `dist` 출력 설정을 사용합니다.
- GitHub Pages 등 일반 정적 호스팅: `npm run deploy:check` 통과 후 `dist` 내용 전체를 게시합니다. `.nojekyll`이 포함되어 있습니다.

직접 문제 링크는 `3d.html?problem=p01`부터 `p26`까지이며, 목록 화면에서도 모든 문제로 진입할 수 있습니다.
