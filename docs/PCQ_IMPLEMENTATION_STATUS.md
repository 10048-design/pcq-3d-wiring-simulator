## 2026-09-12 단자 위치와 간결한 오류 표시 보정

- 전선 곡선의 단자 진입 접선을 단자별로 지정했다. 왼쪽 상단 TB1/TB2는 아래에서 위로 곧게 들어가고, 세로 TB3/TB4는 오른쪽에서 들어간다. PLC 입력부와 릴레이·램프·버튼/셀렉터·MCCB의 위쪽 단자는 위에서 들어간다. 각 기구의 아래쪽 단자는 기존처럼 아래에서 들어가며 압착단자 오브젝트도 같은 방향으로 회전한다. 이 속성은 3D 표시에만 사용하며 Connection/NET 채점에는 영향을 주지 않는다.
- PLC 하단 출력부의 2열 배치를 바로잡아 전원 L/N이 위쪽 줄, E/COM이 아래쪽 줄에 오도록 했다. 단자 ID, 번호와 NET은 변경하지 않았다.
- 첨부 SMPS 사진을 외형 교체나 정답 근거로 사용하지 않고, 기존 `SMPS.L1/N/E/-V/+V`의 체결점을 전면 한 줄로 옮겼다. 화면상 순서는 L1, N, E, -V, +V이며 기존 단자 ID와 NET은 유지한다.
- MC 하단에 A1, A2 체결점을 왼쪽부터 추가했다. `MC.A1 하단`과 `MC.A2 하단`은 각각 상단 A1/A2와 `internalLinks`로 같은 코일 극을 구성하므로 어느 쪽을 사용해도 동일한 전기 NET으로 판정한다.
- TB1/TB2는 하단 나사 4개만, 세로 TB3/TB4는 오른쪽 나사 4개만 선택할 수 있다. 기존 기본 단자 ID를 그대로 사용하고 화면의 상/하 표기를 제거했다.
- 압착단자 재료함에 기존 시험 규칙 데이터의 `1.5-3Blade`, `2.5-4Blade`를 추가하고 Y형과 다른 블레이드 모양으로 표시한다. 선택 상태 유지와 Connection 저장 방식은 기존 흐름을 사용한다.
- 오류 설명은 `TB2 E → TB4 E 연결 X`, `PLC P00 절연튜브 X`, `MC A1 압착단자 X`처럼 짧은 작업 문구로 바꿨다. 기구별 느낌표 묶음, 개수 배지, 클릭 확대와 기존 오류 중복 묶음은 유지한다.
- 자동 검사 48개와 정적 빌드 검증을 통과했다. 3D 하드웨어 데이터는 31개 기구, 223개 단자 레코드(연결 가능 210개), 42개 정답 NET, 3개 내부 도통 링크다.

## 2026-09-12 테이핑 경로와 오류 마커 정리

- 4페이지 기구배치도와 실습 사진을 기준으로 세로 테이핑 구간을 상·하 가로 통로 사이로 제한했다. 왼쪽 세로 통로는 TB3/TB4와 MCCB·OCR·MC 사이의 빈 공간(x=-275)으로 옮겼고, 중앙(x=0)과 오른쪽(x=320) 통로도 기구 행과 겹치지 않는 길이로 잘랐다. 가로 통로는 배치도상의 y=217, 76, -215 빈 공간을 유지했다.
- 오류 마커는 채점 오류 하나마다 만들지 않고 단자 오류는 기구/단자대별, 전선·연결·경로 오류는 Connection별로 묶는다. 빈 배선 채점 기준 78개 오류가 화면에는 17개 위치 마커로 표시되는 것을 브라우저에서 확인했다.
- 마커는 첨부 예시처럼 빨간 원 안의 흰 느낌표로 바꾸고, 같은 위치의 오류가 2개 이상이면 오른쪽 아래 작은 숫자 배지를 표시한다. 확인한 마커는 옅어지지만 사라지지 않는다.
- 마커를 누르면 그 위치로 확대하고 묶인 오류를 한 팝업에 표시한다. 설명은 NET 같은 내부 용어를 숨기고, 연결 누락은 채점 엔진의 실제 권장 연결 쌍을 사용해 “어디에서 어디로 연결해야 하는지” 설명한다. 전선 색상/종류/굵기, 압착단자 크기, 절연튜브, 압착 방향도 작업자가 바로 고칠 수 있는 문장으로 변환한다.
- 이 변경에서는 기존 3D 기구, Terminal, Connection, 상태 머신, Graph/Netlist 및 JUMP 채점 구조를 수정하지 않았다.

## 2026-09-12 시각적 작업 흐름 개편

- 큰 하단 작업 배너와 피복 제거·압착 버튼, 전선 선택 드롭다운을 제거했다. 모든 재료 선택은 3D 작업판 내부 하단의 재료함에서 이뤄진다.
- 전선은 갈색·검정·회색·녹색 단선과 노란 연선을 짧은 입체 조각으로 표현한다. 저장 데이터에서는 녹색 단선을 기존 채점 정책의 녹색-노란색 값으로 유지한다. 노란 연선은 휘어진 형태로 단선과 구분한다.
- Y형 압착단자는 포크와 배럴 모양으로 표시하고 규격명만 작은 글씨로 둔다. 절연튜브는 튜브 오브젝트와 X 아이콘으로 사용/미사용을 선택한다.
- WiringController에 안내형 상태 머신을 추가했다: 전선 선택 → 시작측 튜브 → 시작측 압착 → 시작 단자 → Waypoint 경로 → 목적 단자 예약 → 끝측 튜브 → 끝측 압착 → 자동 Connection 생성.
- 전선 선택 시 노출 도체가 있는 준비 오브젝트를 만들고, 튜브와 압착단자 선택 시 해당 오브젝트를 추가한다. 재료 선택 버튼의 상승 효과와 준비 오브젝트의 짧은 확대/부유 애니메이션으로 가공 과정을 표현한다.
- 시작측/끝측 자재는 ends.from/to에 독립 저장하며, 내보내기 호환 필드 startCrimpTerminal, endCrimpTerminal, startInsulationTube, endInsulationTube, startCrimpOrientation, endCrimpOrientation도 Connection에 함께 저장한다.
- 사용자가 작업판을 클릭한 좌표는 via 안의 point, waypoints, path에 저장되고 Catmull-Rom 곡선의 실제 제어점으로 사용된다. 기존 CT 관통 ID도 같은 via 배열에서 계속 지원한다.
- 왼쪽 상단에는 현재 필요한 동작 한 줄만 표시한다. 오른쪽 상단에는 기본 보기, 실행취소, 선택 배선 삭제, 현재 전선 취소를 아이콘 중심으로 배치했다.
- 완성 전선의 3D Mesh를 직접 클릭해 Connection을 선택할 수 있으며, 선택 강조 후 해당 Connection만 삭제한다. 실행취소는 draft의 마지막 Waypoint·재료·단계부터 되돌리고 draft 이력이 없으면 최근 Connection 변경을 되돌린다.
- 채점 Error는 기존 식별자에 더해 errorId, errorType, relatedDevice, relatedTerminal, relatedConnection, relatedPathSegment, markerPosition, title, reason, expected, actual, correctionGuide 호환 필드를 가진다. 3D 오류 마커가 이를 직접 사용하며 같은 위치의 여러 마커는 원형 오프셋으로 겹침을 줄인다.
- 기존 Terminal 객체 참조, Connection from/to/ends, Graph/Netlist, JUMP 허용 판정과 결정론적 채점 로직은 유지했다.
- 자동 검사 44개 통과. 빌드 검증은 26개 PDF, 31개 기구, 183개 연결 대상 단자, 45개 정답 NET을 통과했다. 새 브라우저 탭에서 전선 선택 → 시작측 튜브/압착 → 실제 3D 단자 선택 → Waypoint → 목적 단자 예약 → 끝측 튜브/다른 규격 압착 → 자동 Connection 생성까지 확인했고 콘솔 오류는 없었다. 이 과정에서 시작 단자 선택 전 포인터 null 처리와 튜브 준비 오브젝트 import 오류를 찾아 수정했다.

남은 확인 사항: Waypoint의 음영 배선 통로 이탈 자동 판정은 아직 route.assessment=미검사로 남아 있다. 압착과 나사 체결 애니메이션은 경량 오브젝트 전환으로 구현되어 있으며 실제 공구 물리 시뮬레이션 수준은 아니다. 단자 좌표 자체는 기존 상태대로 도면 비례값이며 실측값으로 확정하지 않았다.

- `3d.html`의 문제 자료 뷰어에 확대/축소, 화면 맞춤, 시계방향·반시계방향 90도, 180도 회전, 전체화면을 추가했다. 회전 상태와 배율은 `viewer-state.mjs`로 관리하고 `localStorage`에 보관하므로 페이지 탭을 바꾸거나 배선을 진행해도 유지된다. 회전된 가로/세로 크기를 계산해 맞춤 및 확대가 모두 정상 동작한다.

## 자료 범위와 재사용

PDF 26개의 첫 6쪽 분석 및 `dist/assets/p01..p26/1..6.webp`를 재사용했다. 전체 문제의 4–6쪽을 유형별로 대조했고 시험 PDF 7쪽 이후는 사용하지 않았다. 제조사 매뉴얼의 페이지 제한은 시험 PDF에 대한 제한과 다르므로 필요한 제조사 페이지는 확인했다.

기존 `problem.mjs`, `app.mjs`, 2D 화면, 원본 페이지, 규칙과 시험 진행 상태를 최대한 유지했다. `engine.mjs`의 확장은 선택적 속성으로 적용하여 기존 23개 검사가 계속 통과한다.

## 확정된 단자 데이터

`hardware.mjs:createHardwareProblem()`이 유일한 3D 문제 생성 진입점이다. `docs/hardware-data.json`은 그 결과의 인수인계용 스냅샷이며 직접 편집할 원본이 아니다.

각 Terminal:

```text
id / terminalId, deviceId, name, displayNumber, physicalNumber, function
localPositionMm, positionMm, actualPositionMm, normal
connectable, numberStatus, positionConfidence, sourceKey
allowedWires, crimp / requiredCrimp, insulationTube / insulationTubeRequired
maxConnections, orientationRule, doubleCrimpRule, multiMountRule
```

- `p.terminals`, `p.terminalMap[id]`, `device.terminalObjects` 및 `Mesh.userData.terminal`은 **같은 객체**를 참조한다. ID로 새 Terminal 복제본을 만들어 선택하면 WiringController가 거부한다.
- 채점 엔진은 릴레이 비극성 계산 시 NET 목록만 복제하며 Terminal 객체는 유지한다.
- `physicalNumber`는 PLC에서 IN/OUT TB 번호를 뜻한다. `displayNumber`는 P00/P40/COM 등 기능 각인이다.
- 연결을 마친 Connection은 저장/내보내기 가능한 단자 ID를 가진다. 화면에서는 해당 ID를 공용 `terminalMap`으로 해석한다.
- `allowedWires`가 빈 배열이면 해당 단자에 대해 명시 정책을 찾지 못했다는 뜻이며 금지 선언이 아니다.

### 주요 수정

- GMP22-3T에 기존 논리 모델의 `OCR.L1..L3/T1..T3` 나사 단자를 만들지 않는다. TB1→MC 입력 전선이 CT 구멍을 통과한다. 기존 상전원 NET과 OCR–MC NET을 상별로 합쳤다. OCR 전면 6개 나사는 A1,A2,95,96,97,98이다.
- MC의 43/44와 31/32는 공식177쪽으로 확인했다. 더 큰 MC 모델의 13/14와 21/22로 임의 치환하면 안 된다.
- TB1/TB2는 하단, TB3/TB4는 오른쪽의 한 체결점만 등록한다. 상/하 별칭과 TB 내부 링크는 만들지 않는다.
- MC A1/A2는 상단과 하단 체결점을 각각 같은 극의 `internalLinks`로 묶는다.
- 인버터의 두 CM은 공통 기능에 따라 내부 연결한다. 스위칭 접점·PLC 출력 COM·MC 주접점·릴레이 접점은 내부 합선하지 않는다.

## 시험 규칙과 별도 연습 규칙

대표 문제 1–2쪽 기준:

- 주회로: 2.5㎟ 단선, L1 갈색/L2 검정/L3 회색. N은 대표 도면 지정 갈색.
- 보조회로: MCCB 2차 이후 포함 1.5㎟ 노란 연선.
- 보호도체: 2.5㎟ 녹-노 단선.
- 2.5-4Y: MC 주접점/TB, 2.5-3Y: PLC·인버터·SMPS 접지 및 인버터 주회로.
- 1.5-4Y: 램프/셀렉터/버튼, 1.5-3Y: 릴레이/OCR/MC 보조접점/SMPS/PLC 입출력.
- **Blade도 보존:** MCCB 1차 2.5-4Blade, MCCB 2차 및 MC 코일 1.5-3Blade. 사용자 예시 Y 4종만 남기면 이 문제 정답을 만들 수 없다.
- PLC **모든 단자** 절연튜브. 잘못된 미사용 연결도 허용하며 채점에서 검출한다.
- 일반 한 나사 최대2가닥, 나선2mm 이상/피복 물림/조임 불량은 하나의 끝점 체결 오류. 인버터 주회로는 제조사 인쇄27쪽의 한 단자 두 전선 금지에 따라 최대1가닥.
- Y 정상/뒤집힘 및 2개 등을 맞댐은 **이번 사용자 요청의 연습 기준**이다. 시험지 1–6쪽에 해당 방향의 상세 정의가 없다는 기존 분석은 유지한다. 이 기준을 PDF 공식 감점 근거라고 표시하지 않는다.
- PLC 제조사 권장 케이블(입력0.3㎟, 출력0.3–0.75㎟)과 시험지1.5㎟는 구분하여 기록했다. 시험 자재 채점은 시험지를 우선하고 실물 체결 적합성은 확인 필요다.

## 3D 구조

- `scene-geometry.mjs`: 경량 Box/Cylinder/Extrude 기반 기구, 실제 열린 CT 구멍, 나사/확대 히트 영역, Y 포크/배럴/튜브, Curve 전선.
- `workbench-3d.mjs`: WebGLRenderer, PerspectiveCamera, OrbitControls, 광원, 카메라 복귀/기구 확대, 단자 라벨, Raycaster, 강조, 포인터 추적.
- 좌표: board 700×600mm, 중심(0,0,0), 오른쪽+X/위+Y/전면+Z. PDF4의 기존 기구 외곽 중심을 698×599 이미지에서 mm로 변환했다. TB3/TB4는 세로 방향이다.
- 실제 제품 치수를 확인한 PLC/MC/OCR은 공식 몸체 비율을 사용한다. PDF 도식의 외곽 크기를 실물 치수로 오인하지 않는다. 외곽 중심은 PDF 배치 위치를 보존한다.
- 커버는 체결 위치를 볼 수 있도록 개방한 단순 모델이다. 세부 케이스·플랜지·DIN 고정·단자 커버·접촉 블록의 완전한 CAD 재현은 아니다.
- 단자 스크루에 대응하는 투명 히트 영역으로 작은 단자를 선택한다. 기구 확대 후 번호 라벨과 같은 객체를 사용하는 단자 목록도 선택 가능하다.
- 전선은 `CatmullRomCurve3` + `TubeGeometry`. CT 경유점은 전선의 `via` 배열에서 생성한다. 전선 모델과 오류 강조는 같은 Connection 데이터에서 재생성한다.

## 배선 구조와 조작

`wiring-controller.mjs`의 WiringController가 재료 선택, 준비 단계, draft, Connection 확정을 관리한다.

1. 문제 확인 후 시작.
2. 전선 종류/압착단자/튜브/방향/다중 체결 상태 선택.
3. 피복 제거 → 압착 장착. 작업판의 준비 전선에 구리 노출/압착 표시.
4. 시작 단자를 선택하면 해당 Terminal 객체와 시작 끝점 재료를 draft에 고정.
5. 반대쪽 끝은 포인터를 따른다. 이때 끝점 압착/튜브 선택을 바꾸면 도착 끝에 적용된다. 시작 끝은 바뀌지 않는다.
6. 필요 시 OCR CT 구멍 클릭 또는 CT 경유 도구로 관통 추가.
7. 목적 단자 선택 시 Attempt.add로 정확히 하나의 Connection 생성. 확정 전에는 전선 개수/NET에 들어가지 않는다.
8. 선택 자재는 유지된다. 다음 배선은 준비된 상태로 이어서 시작 단자를 선택할 수 있다.

전선 종류/굵기/색상은 시작 시 고정한다. draft 도중 바꾸면 다음 전선의 기본값이 바뀌고 도착 끝의 압착/튜브는 즉시 반영된다. 생성된 전선은 목록에서 선택 후 ‘끝점 자재 수정’으로 수정한다. 이 버튼은 전선 전체 종류/굵기/색상과 선택한 한쪽 끝의 압착·튜브 상태를 적용한다. 목적지 변경은 삭제 후 재결선한다.

Y 오브젝트는 포크 2개/연결부/돌출 배럴로 구성하여 뒤집힘이 실제 형상에 나타난다. 두 번째 체결의 ‘등을 맞댐’은 반전된 배럴과 높이 차로 표현한다. 튜브는 파란 슬리브로 표시한다. 한쪽마다 독립 상태를 저장하며 단자에 연결된 끝점 개수로 1개/2개 상태를 계산한다.

## NET/JUMP와 오류 개수

- `connectionNets()`는 실제 연결 전부와 구조상 내부 도통을 UnionFind로 묶어 사용자 NET을 생성한다. 잘못된 배선도 그대로 반영하여 내보낸다.
- `grade()`는 정답 NET의 최종 도통을 비교한다. A–B–C/A–C–B, 상하 같은 TB 극 사용 등 동등한 연결을 허용한다.
- 전기적 연결과 재료/끝점/CT 관통 검사를 분리한다. CT 미경유는 전기적 NET 단절 오류로 중복 계산하지 않는다.
- 잘못된 전선은 전선 하나당 전기 오류 하나. 단절 NET의 k개 성분은 k−1개 복구 작업. 잘못된 전선 하나가 설명하는 단절 하나만 같은 오류로 흡수하여 독립 누락을 숨기지 않는다.
- 색상과 압착, 튜브와 방향 등 서로 다른 작업은 별도 오류. 2개 Y 체결 불량은 해당 나사 기준 1개. 끝점 체결 불량은 여러 조건이 동시에 나빠도 1개.
- 오류에는 id/type/deviceIds/terminalIds/wireIds/wrong/correct가 저장된다. 결과 클릭 시 기구 확대 및 단자/전선 강조.
- `completeAssessment:false`: 정답/시공 불확실성 때문에 완전한 공식 합격 판정을 하지 않는다. 점수는 없고 틀린 항목 개수만 표시한다.

## 알려진 제한 및 확인 필요

1. **단자 실측 좌표 미확정**. 공식 정면/측면 도면에서 비례로 배치했으나 나사 중심 XYZ 공차를 검증할 CAD/실측이 없다. 단자 번호 선택 정확성 검사와 좌표 실측 정확성은 다르다.
2. 현재 경량 3D 외형은 이 단계의 고정 표시물이다. 버튼류는 작업용 접속부를 전면에 노출한 형태이며 실제 뒤쪽 접점 블록을 정밀 재현하지 않는다. 사용자 사진의 배선을 정답 NET으로 사용하지 않았다.
3. MC 코일은 상단·하단 A1/A2를 각각 같은 극으로 등록했다. 인버터 추가 PE 체결 위치는 완전 열거하지 않았다.
4. PLC의 2열 스크루 행 방향/피치와 G100C 각 블록의 정확한 XYZ는 실물 또는 CAD와 다시 대조할 것. G100C 제어 단자 번호는 2021 C형 기능 기준이고 배치는 그 문서의 도면 비례 참고다.
5. TB는 지정된 한쪽 나사만 선택할 수 있다. MC A1/A2의 상·하 체결점은 같은 극이지만 각 나사의 수용량은 별도로 검사한다.
6. SMPS/전원 접지는 시험지1쪽 TB4 지시와5쪽 TB2 E 그림이 상충한다. 기존 보류 NET을 유지했다.
7. 전선 덕트 자동 라우팅, 기구 관통/충돌 방지, 타이 간격, 실제 조임·피복 길이는 자동 물리 검사하지 않는다. 3D에서 매끄럽게 그려진 선이 시공 규정 준수를 의미하지 않는다. CT는 명시된 경유 선택을 검사한다.
8. Y 규격은 상태값과 간략 폭으로 표현하며 실제 압착단자 제조사별 치수/CAD는 미확정이다. 절연튜브 색은 학습용 표시색이다.
9. 배선 다수일 때 곡선 생성/라벨 겹침/매 프레임 성능은 브라우저에서 확인 필요. 현재 단일 draft의 포인터 이동마다 해당 곡선 형상을 재생성한다.
10. 기존 2D와 3D는 별도의 연습 상태다. 3D 작업은 JSON으로 내보낼 수 있으나 파일 재가져오기나 진행 중 작업 자동 복원은 없다.
11. 태블릿형 브라우저에서 뷰어 회전/확대, 시작부터 채점, 오류 강조는 확인했다. 다시 풀기의 확인창 표시까지는 확인했으나 확인 버튼을 자동화 세션에서 처리하지 못했다. 실제 사용자가 한 번 초기화 결과를 확인해야 한다.
